# opym code review, 2026-11

## Verdict

- Core numerics and the backfill receiver's write path are sound and well tested (389 non-GPU tests pass, 0 fail).
- The weak points are at the edges. The rig-to-receiver time contract is broken on real data. Partial volumes and a
  crashed handler can lose or corrupt data silently. A handedness choice (deskew-only vs decon output) is undecided.
- No P0. Eight P1 findings, listed first below. Order of work: [docs/ROADMAP.md](../ROADMAP.md).

## Architecture notes

```
rig PC (pymmcore-gui _argus_stream)                      Argus (micro001)
  FRAME/slab over 4 SSH links  --5555-->  opym-receive (stream/receiver.py)
                                            |  raw OME-Zarr mirror (stage on /dev/shm, drain to GPFS)
                                            |  live lane (live_zarr.py): ticket per (t,c) in queue_live
                                            v
                              opym-serve (local_gpu_worker.py): one MATLAB PetaKit5D server per GPU
                                            |  decon -> deskew -> view buffers + processed OME-Zarr
                                            v
                              viewer/<base>_dsr.ome.zarr  ->  naparym-live, CORE live QC, dashboard
  finished stores --5556--> opym-receive-backfill (readback-verified, .opym_complete.json)
                                            v
                              opym-backfill (bioimaging): discovery + registry -> queue (batch lane)
```

- Two console scripts live here (`opym`, `opym-add-times`); bioimaging declares ten more and owns the systemd units.
- Source is about 23.5 kLOC of Python and MATLAB. Largest: `live_view.py` (2243), `stream/receiver.py` (2144), `petakit.py` (1154), `run_petakit_server.m` (1027).
- Shared state: `/dev/shm/petakit_jobs` (queues, leases, claims), `/dev/shm/opym_stream_stage`, `/dev/shm/opym_live_view`, the sqlite registry on `/mmfs2`.
- Live work has priority: `LIVE_LEASE.json` (60 s) and `WARM_LEASE.json` (600 s) keep the batch lane off the GPUs.
- Production runs from the `opym_local` checkout through bioimaging's venv (editable). Pulling main without restarting the `opym-*` units is a partial deploy.
- The four units that run opym (`opym-receive`, `-receive-backfill`, `-serve`, `-backfill`) were restarted 2026-10-26 13:56 CDT, after the last opym merge that day, so they ran HEAD at the review date. Decon v2 (synthetic PSF, `pad_z`) is merged but unused in production.
